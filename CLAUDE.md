- When fixing public-domain behavior, consider cache and proxy behavior before assuming application logic is broken.
- When adding or modifying API endpoints, update Pydantic models in `models.py` and add tests in `tests/`.
- Coaching routes live under `/api/coach/*` and require `admin` or `coach`; signed-in player/family feedback lives under `/api/my-feedback`. DB user roles can be comma-separated capability strings (`coach,uploader`), so use `_auth.require_role()` / `_auth.has_role()` and `app.hasRole()` / `app.canCoach()` instead of direct string equality. **Namespace exception**: `GET /api/coach/notes/{note_id}/thumbnail` is the one read-only `/api/coach/*` route reachable by any signed-in user. - Coaching drawings are JSON metadata on `coaching_notes`, rendered by `js/coaching.js` as a canvas overlay. Legacy `version: 1` strokes still render; `version: 2` objects power telestrator tools (`freehand`, `arrow`, `circle`, `zone`, `label`, `spotlight`, `dim`, `formation`). The `formation` type holds 3–16 anchors plus a `hull_points` polygon; per-anchor `player_id` is the forward-compat hook for future animated/tracked phases (see ROADMAP "Coaching Telestrator — Future Phases"). Do not burn drawings into video files unless a future clip-export feature explicitly calls for it.
- Coaching notes carry **Phase 1 structured fields** (PR 1a — `_migrate_v9` in `db.py`): `note_type` (one of `_VALID_NOTE_TYPES` = `positive` / `correction` / `question` / `team_concept` / `individual_goal`, default `correction`), `what_happened`, `why_it_matters`, `what_to_do_next`, `player_summary`, and `coach_private_note`. All optional with safe defaults — legacy clients keep working. **`coach_private_note` is coach/admin-only** — `_filter_notes_for_user` in `server.py` runs every viewer-visible note through `_strip_private_fields()` to scrub it to `""` before any `/api/my-feedback` response. `/api/my-feedback` ALSO embeds note objects under `playlists[].items[]`, so `my_feedback` builds an `items_source` for the viewer branch via `[_strip_private_fields(n) for n in all_notes]` before passing to `_playlists_with_items` — any future viewer-facing surface that embeds notes must follow the same pattern. `player_summary` is the player-facing text and IS visible to viewers by design. PR 1b surfaces the structured fields in the Coach Review composer (`renderCoachReviewForm()` + `setCoachReviewNoteType()` in `js/coaching.js`) and the Notes-tab Edit modal — keep the JS `NOTE_TYPES` array in sync with the backend `_VALID_NOTE_TYPES` set. PR 1c renders the player-facing layer in My Feedback (`renderFeedbackNotes` + the focused-modal `_renderFeedbackBody` + `renderPlaylistSessionRail`): tone pill + `player_summary || body` fallback + optional `<dl>` for `what_happened` / `why_it_matters` / `what_to_do_next`. The modal template's body container was promoted from `<p>` to `<div>` so the `<dl>` markup is valid. Helpers `_feedbackNoteSummary` / `_feedbackTonePillHtml` / `_feedbackStructuredHtml` are the single composition point — defense-in-depth: they never template `coach_private_note`.
- **Coach Review templates (Phase 2)** live in `js/coaching-templates.js` as a static registry: `COACH_TEMPLATES` (array of 14 starter templates grouped by soccer area), `COACH_TEMPLATE_GROUPS` (ordered group names for the `<optgroup>` selector), and `findCoachTemplate(id)`. Each template defines `id` / `label` / `group` / `category` / `note_type` / `title` / `player_summary` / `what_happened` / `why_it_matters` / `what_to_do_next` / `tags`. Templates **never** populate `coach_private_note` — that field stays empty unless the coach types into it. The Coach Review composer renders a Template selector + Apply / Clear buttons via `renderCoachReviewForm()`; `applyCoachTemplate()` writes the structured fields into the existing inputs and uses `confirmAction()` to ask before overwriting coach-typed text (Option A overwrite-protection — defaults like category=`shape` and tone=`correction` count as untouched on a fresh composer). The active-template tracker `_coachReviewActiveTemplateId` resets on save so the next moment starts from "None — start from scratch." When adding a new template, keep its `category` inside `NOTE_CATEGORIES` and its `note_type` inside `NOTE_TYPES` (which mirror the backend `_VALID_NOTE_TYPES` set).
- **Per-coaching-note thumbnails (Phase 3a, backend-only)** live at `<videos>/<match_id>/coach_thumbs/<note_id>.jpg`, resolved via `_media.coach_note_thumbnail_path(VIDEOS_DIR, match_id, note_id)`. The path is purely deterministic from `match_id` + `note_id` so no DB column or schema migration is required; the serving endpoint just calls `path.is_file()`. Generation runs as a background `_spawn_task(_spawn_coach_note_thumbnail(note))` from `POST /api/coach/notes` and from `PATCH /api/coach/notes/{id}` (only when `match_id` / `slot` / `timestamp_seconds` change), and uses `_media.generate_thumbnail_at_timestamp(src, dest, timestamp_s=...)` which is best-effort: missing source video, ffmpeg crash, or timestamp past duration all log a warning and return `False` rather than raising — the parent task's response to the coach is never blocked. `DELETE /api/coach/notes/{id}` `unlink(missing_ok=True)`s the JPEG. Serving: `GET /api/coach/notes/{id}/thumbnail` requires any signed-in user (`_auth.require_auth`) and enforces visibility via the new `_can_view_coach_note(user, note)` helper which **reuses `_filter_notes_for_user`** so the visibility ladder cannot drift; unknown notes, notes the user can't see, and missing files all return the same `404` so a viewer cannot probe private-note existence. Manual coach refresh: `POST /api/coach/notes/{id}/thumbnail/regenerate` (gated by `_require_coach`) returns `{ok: true, generated: bool}`. The standalone thumbnail endpoint deliberately does NOT honour the playlist-grants-access boundary for private items — same policy as `/api/my-feedback/notes`. **Caching**: the GET response uses `Cache-Control: no-cache, must-revalidate` + `ETag: "{mtime}"` (mirrors `serve_thumbnail`) — never `public`, because the response is access-controlled per-viewer and a shared cache must not replay it across users. **Path containment**: every site that resolves a coach-note thumbnail path (GET, regenerate POST, background spawn, delete cleanup) runs the path through `_thumb_path_within_videos_dir(thumb)` so a corrupted DB row whose `match_id` contains `..` cannot escape `VIDEOS_DIR` — same defense-in-depth pattern as `serve_logo` / `serve_thumbnail` (commit `e11992d`). Containment-fail in GET returns the same 404 as the unknown / unauthorized / missing-file cases.
- **Per-coaching-note thumbnails (Phase 3b, UI integration)** wires the Phase 3a endpoints into every surface that renders coaching notes. **The serving endpoint requires a Bearer header**, which `<img src>` cannot send, so `js/api.js` exposes `loadCoachNoteThumbnail(noteId)` (auth-fetch → blob → `URL.createObjectURL`) and `mountCoachNoteThumbnailsIn(container)` (one-pass mount of `<img data-coach-note-thumb="<id>">` placeholders). A per-note Map cache dedupes concurrent fetches AND negative-caches 404 / 403 / network failures so a long timeline rail doesn't re-fire requests every render. Object URLs are revoked on `setLoggedOut()` so blobs from a prior session don't outlive their visibility context — and on `regenerateCoachNoteThumbnail()` so a refreshed JPEG appears immediately. The single primitive `_coachNoteThumbHtml(note, { size })` in `js/coaching.js` produces a `.coach-thumb` tile in five size variants (`list` / `card` / `chip` / `rail` / `strip`) with a CSS `::after` film-strip placeholder so the no-thumbnail case never touches the network and never flashes a broken-image icon. Surfaces wired: Coach Notes list (with a coach-only ↻ Regenerate action that calls the existing endpoint), Coach Review timeline rail (`coach-timeline-chip--with-thumb`), Coach Playlists row (stacked `.coach-thumb-strip` of first 3 notes + `+N` overflow), My Feedback notes (220 px-thumbnail-left + body-right grid, mobile-stacks at 720 px), My Feedback playlists (first-item cover thumbnail), and the playlist session rail (active-item tile). The note picker inside the playlist edit modal stays text-only — a multi-select check list with thumbnails would change its UX meaningfully and is intentionally deferred. **Privacy**: every fetch goes through the visibility-checked GET endpoint; a viewer who can't see a note simply gets a placeholder. There is no client-side role check and no client-side authorization logic.
- **Coaching clips (Phase 4a, backend only)** are first-class objects representing a saved `[start_seconds, end_seconds]` window of a match slot. Schema lives in `coaching_clips` + `coaching_clip_players` (`db.py` `_migrate_v10`); fields mirror `coaching_notes` so the visibility ladder + linked-player rules apply unchanged. Endpoints under `/api/coach/clips` (`GET`, `GET/{id}`, `POST`, `PATCH/{id}`, `DELETE/{id}`) are coach/admin-only via `_require_coach`; clips are also embedded under `/api/my-feedback` filtered by `_filter_clips_for_user` (same shape as `_filter_notes_for_user`). MVP duration cap is `_MAX_CLIP_DURATION_SECONDS = 120.0` in `models.py`. **Privacy invariant**: `source_note_id` is OPTIONAL. When a clip is created with one, the ONLY field defaulted from the source note is the drawing snapshot (and only when the request body didn't already provide a `drawing`). All other clip fields — `match_id`, `slot`, `start_seconds`, `end_seconds`, `title`, `description`, `category`, `visibility`, `player_ids` — come from the explicit clip request and are NOT validated against the source. `body` / `coach_private_note` / `what_happened` / `why_it_matters` / `what_to_do_next` / `player_summary` / source-note title are NEVER auto-copied into the clip's response, so a coach-private note's text cannot be re-published under a more permissive clip visibility. Clip storage carries no text fields from the note — only the coach's request-body `title` + `description`. **No MP4 export yet**; playback remains seek-based against the source match video. **No clip thumbnails yet**; clips reuse the source note's existing thumbnail when relevant. **No clip authoring UI yet** — the Coach Review surface ships in Phase 4b. `delete_coaching_note` explicitly NULLs the `source_note_id` FK on referencing clips because SQLite's `ON DELETE SET NULL` requires `PRAGMA foreign_keys = ON` which the rest of the codebase doesn't enable; the snapshot drawing on the clip stays valid after the source note is deleted.
- Review playlists expose ordered `items` for playback. A visible playlist grants access to its item moments inside the playlist session even when those notes are private as standalone feedback.

- Coach Review's Wide / Focus mode (PR #59) hides page chrome and the inspector to maximise the video + canvas. Implementation note: `openCoachFocusInspector()` in `js/coaching.js` re-parents `.coach-review-side` to `<body>` while open and restores the original DOM position on close. This is required because `.coach-tab-panel` has an `animation` property that creates a bounded stacking context — without re-parenting, the drawer's `z-index` is trapped and the backdrop renders above it (intercepting clicks). - Match URLs use slug-based deep links (`/match/{slug}`, `/match/{slug}/first-half`). The Watch Live page deep-links to `/live`.
- Live streaming runs through a `mediamtx` sidecar in compose. Camera-facing surface is RTMP at port 1935; browsers play LL-HLS via the proxy at `/api/live/hls/*`. Never expose MediaMTX's 8888/9997 ports publicly — they stay on the internal compose network.
- When setting video status to `"error"`, always pass `error_info` dict with `error_code`, `reason`, `details` to `_set_video_status()` so errors are persisted to the `video_errors` table.

- Performance tuning knobs (transcode concurrency, hwaccel choice, HLS segment duration, upload limits, ABR ladder) are stored in the `settings` table — not hardcoded constants. Read live values via the `current_*()` helpers in `server.py` (e.g. `current_transcode_concurrency()`, `current_replay_hwaccel()`); each helper resolves through `settings.load_unlocked()`. Schema and validation lives in `settings.TUNING_KNOBS`. When adding a new knob: add it to `TUNING_KNOBS`, add a default to `DEFAULT_APP_SETTINGS`, add a `current_*()` helper if needed, surface it in `js/admin-views.js` via `renderTuningKnobsCard()`, and update the relevant `current_*()` consumer call sites.
- The transcode semaphore is a `ResizableSemaphore` (defined in `server.py`); `PUT /api/admin/settings` calls `TRANSCODE_SEMAPHORE.resize()` when `transcode_concurrency` changes so the change is live without a restart. Don't replace it with a plain `asyncio.Semaphore`.
- HLS cache headers must stay aligned with `live.py`'s proxy policy: playlists `public, max-age=60, must-revalidate`, segments `public, max-age=31536000, immutable`. The `Caddyfile` mirrors these — keep both in sync if the policy changes.
- Match-logo responses must emit `X-Content-Type-Options: nosniff`, `Content-Security-Policy: script-src 'none'`, and `Content-Disposition: inline` — defense-in-depth against stored XSS via uploaded SVGs (logo upload is admin/uploader-gated, but a compromised account or a careless paste of a third-party SVG should not be able to execute script in the replay app's origin). Both the FastAPI `serve_logo` route and the Caddy `@match_logo` block must keep these headers. Three places must stay in sync: `server.py` (`serve_logo`), `Caddyfile`, and the inlined Caddyfile in `docker-compose-intel.yml`.
- Storage tiering: HLS variants + thumbnails go on `VIDEOS_DIR` (SSD, hot path). Raw uploads + finished MP4s go on `ORIGINALS_DIR` (cold pool when `REPLAY_ORIGINALS_DIR` is set; otherwise aliased to `VIDEOS_DIR`). When adding a new path that holds a `<slot>.mp4` or `<slot>_raw.*` file, route it through `_slot_mp4_path()` / `_slot_raw_path()` / `_find_slot_raw_path()` in `server.py` (or the underlying `media.py` helpers) — never construct `VIDEOS_DIR / match_id / f"{slot}.mp4"` directly. HLS paths still use `_slot_hls_dir()` / `_slot_hls_master_path()` and stay on the SSD.
- The Caddy reverse proxy serves VOD HLS segments directly from the `/data` bind-mount; everything else is proxied to the replay app on `:8090`. Keep the URL pattern `^/api/matches/{id}/hls/{slot}/...` stable so the Caddy regex routes match. Because segments bypass FastAPI, the streams registry would otherwise lose VOD sessions to its 15 s idle reaper; `js/player.js` POSTs to `/api/matches/{id}/heartbeat?slot=…` every 10 s while playback is active to call `registry.touch("vod-hls", …)` and keep the session warm. If a heartbeat returns 403 the player stops — that's how an admin "kill" propagates to VOD viewers.
- The Performance Tuning panel polls `/api/admin/performance` every 5 s while `/admin/performance` is active. Add new signals by extending `_host_signals()` / `_disk_pools()` / the response payload — the frontend tile list in `renderPerformanceTuning()` is a flat array, easy to extend.
- Tuning knobs save through a dedicated `handleTuningSubmit()` (NOT `handleSettingsSubmit()`). - Live auth hardening: `/api/live/auth` now fails closed (503) when `LIVE_AUTH_SECRET` is unset unless `LIVE_AUTH_ALLOW_INSECURE=1` is explicitly set for dev-only use.
- Live auth secret transport: MediaMTX 1.18 dropped `authHTTPHeaders`. The shared secret now travels as the password half of HTTP Basic Auth in `authHTTPAddress` (e.g. `http://_:${MTX_LIVE_AUTH_SECRET}@replay:8090/api/live/auth`). The handler accepts both `Authorization: Basic …` (current) and `X-Internal-Secret:` (legacy) — keep both paths working when touching the handler.
- Live auth webhook tests should set `server.LIVE_AUTH_SECRET` and send the secret as either `X-Internal-Secret` or HTTP Basic Auth so stream-key validation is exercised behind the MediaMTX shared-secret gate.
- `pytest.ini` pins pytest-asyncio fixture loop scope to `function` and narrowly filters dependency-owned Python 3.14 asyncio deprecations so local test runs stay warning-clean.
- Auth token cap is configurable with `MAX_ACTIVE_TOKENS` (default 1000).
